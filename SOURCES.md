## Conflicts and rules for resolving them

- ARCHITECTURE.md describes AND/MUL and says the Binius64 system is non-ZK. Current constraint.rs includes Zero, And, Imul, and Bmul; zk_config.rs supplies the separate ZK composition. Treat the architecture document as an incomplete summary.
- Crate-level prover/verifier comments describe ZK broadly, while plain Prover/Verifier function bodies explicitly select non-ZK operation. Read the called implementation.
- The older blog index says integer multiplication was not yet in the live codebase. Current prove.rs invokes intmul::prove. Historical prose is not current implementation evidence.
- Keep specification claims, observed implementation behavior, and inferred motivation distinct.
- A 128-bit challenge field alone is not a proof of 128-bit end-to-end security. Derive the actual error and cryptographic parameter bounds later.
- The Blueprint distinguishes succinct proof size from current verification time: the verifier reads circuit data. Preserve that qualification.
